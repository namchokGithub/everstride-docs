# Phase 3.2 — Adventure UI Skeleton — Implementation Plan

> **For agentic workers:** Implement the tasks in order. This phase is a UI
> reskin; do not expand it into Phase 4 Adventure game logic.

**Goal:** Turn the existing temporary Adventure screen into a Greenwood Trail
selection screen matching the product mockup while preserving the current
10-Energy temporary Adventure action.

**Design:** `everstride-docs/specs/2026-09-09-phase3.2-adventure-ui-skeleton-design.md`

**Constraints:** Keep business logic in `PlayerController`; do not add an
Adventure model, persistence, assets, dependencies, routes, item rewards, or
difficulty balance. The existing `spendOnAdventure()` contract remains
unchanged.

## Task 1: Add a failing Adventure screen widget test

Create `everstride-mobile/test/features/adventure/presentation/adventure_screen_test.dart`.

- Override `playerControllerProvider` with a fake successful controller.
- Assert Easy is selected initially, then tap Normal and assert its selected
  state changes.
- Tap **Start Adventure · 10 Energy** and assert the fake controller receives
  one `spendOnAdventure()` call and the success SnackBar appears.
- Add a fake failing controller that returns `Err(Failure('Not enough energy'))`
  and assert the existing failure feedback appears.

Run:

```bash
flutter test test/features/adventure/presentation/adventure_screen_test.dart
```

Expected before Task 2: fail because the current screen has no difficulty UI
or new CTA.

## Task 2: Reskin `AdventureScreen`

Modify `everstride-mobile/lib/features/adventure/presentation/screens/adventure_screen.dart`.

- Convert it to `ConsumerStatefulWidget`; store a private local difficulty
  enum/state with Easy as the default.
- Render Greenwood Trail title/description, existing `bg.png` artwork,
  Easy/Normal/Hard `ChoiceChip`s, the Phase 4 explanatory note, and cards for
  `+25 EXP` and `+10 Gold` only.
- Render a full-width `ElevatedButton.icon` labelled
  **Start Adventure · 10 Energy**.
- Invoke the unchanged `PlayerController.spendOnAdventure()` method. Show
  `Adventure complete! +25 EXP, +10 Gold` on `Ok`; show `Failure.message` on
  `Err`.
- Do not pass selected difficulty into any controller, use case, repository,
  or database layer.

## Task 3: Verify and record progress

Run:

```bash
flutter test test/features/adventure/presentation/adventure_screen_test.dart
flutter analyze
```

Manual check:

1. Open Adventure from Home; Greenwood Trail, three chips, and two implemented
   reward cards appear.
2. Tap each difficulty; only selected styling changes.
3. With at least 10 Energy, Start Adventure deducts 10 Energy and grants
   +25 EXP/+10 Gold, then shows the success SnackBar.
4. With less than 10 Energy, the existing `Not enough energy` SnackBar appears
   and Player state does not change.

Update `everstride-docs/PROGRESS.md` so Phase 3.2 links to the design spec.
