# Phase 3.2 — Adventure UI Skeleton — Design

Status: approved, ready for implementation

Relates to: `everstride-docs/specs/2026-09-08-phase3.1-ui-foundation-design.md`,
`everstride-docs/image/draft_design.png`, and Phase 4 Adventure MVP.

## Goal

Reskin the existing Adventure tab into the first Adventure-selection surface
shown in the product mockup. The screen should communicate the intended
Adventure shape without changing the Phase 3 temporary gameplay contract.

This phase is UI-only. It does not introduce Adventure entities, persistence,
items, balance data, navigation, an in-progress state, a result screen, or
atomic Adventure transactions.

## Player Experience

The Adventure tab presents one static Adventure:

- **Greenwood Trail** — “A peaceful path through the forest.”
- A rounded trail image using the existing `lib/assets/bg.png` asset.
- Difficulty chips: Easy, Normal, and Hard. Easy is selected initially.
- A concise note that difficulty effects arrive in Phase 4.
- A Possible Rewards row that lists only `+25 EXP` and `+10 Gold`.
- A full-width **Start Adventure · 10 Energy** action.

Difficulty selection is local screen state only. It changes selected styling,
resets when the screen is recreated, and does not change the Energy cost,
rewards, controller call, or persisted data.

## Gameplay Contract

The Start Adventure action continues to invoke
`PlayerController.spendOnAdventure()` without parameters. Its existing
temporary behavior remains the source of truth:

```text
10 Energy → +25 EXP, +10 Gold
```

On success, the screen remains open and presents a short SnackBar:
`Adventure complete! +25 EXP, +10 Gold`.

On failure, it presents the existing failure message, including
`Not enough energy`. No difficulty-specific failure or reward behavior exists
in this phase.

## Scope Boundaries

Included:

- Adventure-tab presentation, local difficulty selection, implemented reward
  preview, and existing action feedback.
- A widget test covering selection and both action outcomes.

Deferred to Phase 4:

- Data-driven Adventure definitions and difficulty balance.
- Loot, items, crystals, leaves, combat stats, equipment, and real reward
  results.
- In-progress/resolve screens, Adventure history, and atomic transactions.

No new dependencies, assets, routes, database tables, repository methods, or
domain models are required.
